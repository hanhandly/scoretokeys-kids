# 小琴伴 (ScoreToKeys Kids)：产品需求与技术方案

> 版本：2.0  
> 日期：2026-08-19  
> 项目路径：`C:\hannahlocal\Workspaces\scoretokeys-kids`

## 1. 产品定位

小琴伴 (ScoreToKeys Kids) 面向儿童电子琴初学者、家长和启蒙教师，把用户提供的数字简谱、五线谱、MusicXML、MIDI、PDF 或乐谱图片转换为可校对、可打印、可播放和可跟练的儿童教学材料。

核心体验：

```text
输入乐谱
→ 多模型独立识别和证据校验
→ 用户确认
→ 生成右手指法与分级左手伴奏
→ A4 教学谱、音频、键盘和手指同步
→ 慢速、循环和自动跟随练习
→ 导出一致的 PDF、MusicXML、MIDI、音频和视频
```

产品不替代教师，也不承诺无需校对地识别任意复杂、手写或低质量乐谱。

## 2. 核心原则

1. **忠实原图**：不得根据熟悉旋律静默改谱；
2. **分歧不静默**：模型和规则无法确认时必须人工处理；
3. **证据可追溯**：每个事件关联原图位置、模型、提示词和确认来源；
4. **单一音乐事实**：谱面、声音、动画和导出来自同一领域模型与时间线；
5. **版式可阅读**：优先保持原谱谱行、小节和歌词关系；
6. **算法可解释**：指法、和弦及验证规则可重复、可测试、可修改；
7. **隐私最小化**：只向模型发送必要乐谱内容。

## 3. 目标用户

- 初学电子琴的儿童；
- 陪练和制作练习材料的家长；
- 儿童音乐启蒙教师；
- 需要把现有儿歌谱转换成简化教学材料的用户。

## 4. 输入

### 4.1 正式 MVP

- 文本数字简谱；
- MusicXML；
- MIDI；
- 清晰印刷五线谱图片或 PDF；
- 清晰印刷数字简谱图片或 PDF；
- 应用内音符和琴键录入。

### 4.2 后续能力

- MuseScore 原生文件；
- 复杂多声部钢琴谱；
- 低质量拍照；
- 手写谱；
- 真人 MIDI 键盘跟弹和错音反馈。

### 4.3 图片预处理

- 文件格式和魔数校验；
- 页面拆分；
- 去倾斜和透视矫正；
- 裁边、去阴影和对比度增强；
- 整页、谱行和小节多尺度裁剪；
- 页面、谱行、小节和歌词区域坐标；
- 原图及每个裁剪的内容哈希。

## 5. 多模型识别

### 5.1 模型角色

| 角色 | 模型 | 设置 |
|---|---|---|
| Reader A | GPT-5.5 | `long_context`、`xhigh` reasoning |
| Reader B | Gemini 3.1 Pro Preview | `long_context`、最高可用 thinking |
| Reader B 成本回退 | Gemini 3.7 Flash | 最高可用稳定设置 |
| Judge C | GPT-5.6 Sol | `long_context`、`max` reasoning |
| 校验和导出实现 | GPT-5.3 Codex | `xhigh` reasoning |
| 独立代码复核 | MAI-Code-1.1-Flash | 最高可用设置 |
| 剩余语义裁决 | GPT-5.6 Sol | 测试无法裁决时使用 |

系统必须记录实际生效配置。模型不支持某项设置时应明确记录，而不是伪装为已启用。

### 5.2 独立读取

Reader A 和 Reader B：

- 并行读取相同来源证据；
- 互相不能看到对方输出；
- 使用相同版本的结构化 schema；
- 同时读取整页、谱行和当前小节；
- 只转录可见符号；
- 无法辨认时返回 `unknown`；
- 报告页面和小节覆盖，不得遗漏后返回成功。

### 5.3 标准化和差异

程序标准化：

- 小节和事件顺序；
- MIDI 音高及来源音名；
- beat、tick 和时值；
- 弱起、休止、附点和连音；
- 歌词 Unicode 和空白；
- 图像坐标。

差异类型：

- 缺少或多出事件；
- 音级；
- 仅八度；
- 起点或时值；
- 音符与休止；
- 附点、连音和临时记号；
- 歌词文本或对齐；
- 小节、谱行或页面覆盖；
- 来源版式。

缺失、八度、节奏和覆盖差异属于高风险。

### 5.4 Judge

Judge 只处理分歧或规则标记的高风险小节，并读取：

- 原始谱行和小节；
- A/B 标准化候选；
- 双方视觉证据；
- 确定性规则报告；
- 必要的前后小节。

Judge 必须选择完整候选或返回 `unresolved`。不能只凭票数，也不能用音乐常识代替图像证据。

### 5.5 状态

- `reader-agreed`；
- `judge-confirmed`；
- `manual-confirmed`；
- `unresolved`。

只有前三种可以进入已确认标准乐曲模型。当前开发 fixture 必须标记为 `development-fixture`，不能显示成在线双模型确认。

## 6. 确定性校验

- 小节拍数完整；
- 弱起和尾部休止明确；
- 事件不越过小节；
- 调号、谱号、临时记号和音高拼写一致；
- 五线位置或简谱上下点与八度一致；
- 歌词音节与音符对齐；
- 每页、每行和每小节都有覆盖；
- 根音加五度使用真实根音和纯五度；
- 和弦转位保持合法音集合；
- 伴奏不越过显式休止；
- MusicXML、MIDI、JSON、屏幕和音频事件摘要一致。

重复乐句、异常大跳、调式外音、和弦不匹配和授权参考谱只能产生警告，不得自动修改来源音符。

## 7. 人工校对

校对界面需要：

- 原图整页、谱行和小节联动；
- A/B/Judge 差异热区；
- 按音高、八度、时值、休止、歌词和覆盖筛选；
- 采用 A、采用 B、采用 Judge 或人工录入；
- 显示证据和规则结果；
- 锁定已确认事件；
- 撤销、重做和版本历史；
- 确认人、时间、前后值及来源。

未完成校对时禁止编配、播放和导出。

## 8. 教学编配

### 8.1 右手

- 初学者连续指法；
- 儿童和成人手型；
- 黑白键、跨度、穿指、重复音和手位移动成本；
- 支持修改和锁定；
- 重算不能覆盖锁定。

### 8.2 左手

- 单根音；
- 根音加五度；
- 柱式三和弦；
- 分解和弦；
- 低音加和弦。

和弦推荐以可解释规则和动态规划为主。模型只提供建议和解释。

## 9. A4 教学谱

### 9.1 原稿版式

- A4 `210 mm × 297 mm`；
- 重新生成 SVG，不使用原图作为最终背景；
- 优先保持原始谱行数量；
- 保持小节所属谱行；
- 保持歌词断行和段落；
- 指法、和弦和左手提示使用独立轨道；
- 内容不足时留白；
- 内容过多时增加页面；
- 禁止重叠、截断和不可读缩放。

### 9.2 放大练习

- 增大音符、指法和歌词；
- 允许增加谱行和页面；
- 只在小节边界换行；
- 尽量保持乐句和歌词词组。

固定每行四小节只能作为没有来源布局时的回退。

### 9.3 自动跟随

- `event → measure → system → page → SVG element` 映射；
- 每帧更新高亮，只在跨谱行时滚动；
- 当前行保持在视口上方约三分之一；
- 用户滚动、缩放或点击后暂停跟随；
- 提供“继续跟随”；
- seek、循环和恢复播放后定位；
- 打印禁用滚动；
- 支持减少动态效果。

## 10. 统一播放

每个演奏事件至少包含：

- 起点；
- 时值；
- MIDI 音高；
- 左右手；
- 声部；
- 指法；
- 力度；
- 小节；
- 和弦；
- 来源事件。

Web 播放优先使用 `AudioContext.getOutputTimestamp()` 映射浏览器可观测的可听位置，回退到 `outputLatency` 或 `baseLatency`。动画不能独立使用 `performance.now()`。

当前播放基线按 `0829` 实现恢复：先等待 `AudioContext.resume()`，再把全部声部和节拍器安排到 `currentTime + 0.05` 开始的同一音频时间轴。50 ms 是调度提前量，不是设备延迟测量。输出时间戳有效时直接使用，不叠加另一份延迟估计。

播放器只提供一个 `positionBeat`，同时驱动谱面高亮、琴键、指法、进度、读数和自动跟随，暂停恢复及配置变化也使用同一位置。不引入个人或全局偏移、独立画面计时、测试音预热、时钟稳定性等待或麦克风校准；正常练习不要求用户进行专业校准。

音符排程完成不等于输出时钟已经到达首音起点。起点之前保持准备状态，不提前点亮音符或琴键；到达起点后按同一次时钟采样的位置开始呈现。等待期间的暂停、停止、跳转和配置变化必须仍然可取消旧排程；此规则不增加固定补偿，也不重置实际播放位置。

新页面删除本站点旧 `v1` / `v2` / `v3` 音频校准设置，但不读取或迁移它们。不得清除语言偏好或其他浏览器数据。存储删除失败须明确提示，但不能让旧补偿重新进入播放路径。

保留现有界面、双语、识谱校对、生成进度、访问期上传、弱起与连音修正、指法、点击播放及导出。恢复播放链不得回退规范乐谱或覆盖整个旧版 App。

浏览器输出时钟不能独立证明用户最终听到声音的时间，主机回环也不能代替远程客户端的听觉验收。恢复基线不等于已经解决所有设备的音画偏差；不得用 LLM 推测或混入录音回传的往返时间冒充单向播放测量。

练习功能：

- 播放、暂停、停止和跳转；
- `25%`、`50%`、`75%`、`100%`；
- 连续调速；
- 左手、右手和节拍器开关；
- 小节和范围循环；
- 调速不改变音高。

## 11. 输出

- 屏幕 A4 SVG；
- PDF；
- PNG；
- MusicXML；
- MIDI；
- JSON；
- WAV/MP3；
- 带同步音频的 MP4。

所有输出从同一标准乐曲模型、布局计划和演奏时间线生成。导出后需要重新解析 MusicXML/MIDI 并比较语义摘要。

## 13. 质量门禁

### 13.1 金标

初始金标不少于 50 个小节，覆盖：

- 五线谱和简谱；
- 高低八度；
- 临时记号；
- 弱起、附点、连音和休止；
- 多谱行；
- 中英文歌词；
- 页面末尾；
- 轻度倾斜和压缩。

### 13.2 指标

- 音高准确率；
- 八度准确率；
- 时值准确率；
- 歌词字符和对齐准确率；
- 页面和小节覆盖率；
- Reader 分歧率；
- Judge 解决率；
- 人工复核率；
- 自动确认区域静默错误数。

自动确认区域出现未报告错误时，发布回归失败。

### 13.3 工程

- 类型检查；
- 单元和契约测试；
- MusicXML/MIDI 往返；
- A4 视觉回归；
- 浏览器播放和自动跟随；
- 音画同步；
- 生产构建；
- 依赖安全审计。

## 14. 隐私和版权

- 多供应商处理前取得同意；
- 只发送必要乐谱；
- 不发送儿童姓名、照片或无关内容；
- 密钥仅在后端；
- HTTPS、最小权限和保留期；
- 支持删除原图、裁剪、响应、缓存和导出；
- 遵守企业模型策略；
- 演示和内置曲库只使用公版、授权或原创内容；
- 用户上传内容不自动进入共享训练或示例集。

## 16. MVP 验收摘要

1. 图片/PDF 产生两个独立候选；
2. 所有差异进入 Judge 或人工；
3. 每个确认事件可追溯；
4. 无法确认时显式阻塞；
5. A4 原稿模式保留谱行、小节和歌词；
6. 自动跟随不抢夺用户滚动；
7. 声音、键盘、手指、谱面和滚动共用音频时钟；
8. 各输出事件一致；
9. 模型和提示词变化触发金标回归；
10. 不把开发 fixture 伪装成在线识别结果。
