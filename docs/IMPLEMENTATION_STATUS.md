- 2026-09-20 按用户选定的 `0829` 实现恢复播放链：等待 `AudioContext.resume()`，以 `currentTime + 0.05` 为共同排程起点；
- 音频、进度条、谱面、琴键、指法和自动跟随共用 `AudioPlaybackClock.getPositionBeat()` 返回的单一位置与统一 BPM/速度换算，不再分成音频位置和补偿后的画面位置；
- 首音启动使用同一次 `sample()` 的 `positionBeat` 与 `outputStarted`：排程返回后仍保持 `starting`，输出时钟到达计划起点才同时放行谱面和琴键；等待期间可以暂停、停止或重新排程，迟到的首帧直接使用当前拍位，不从起点重新计时；
- 输出时间戳可用时直接使用其映射，不再额外叠加 `outputLatency` 限制；时间戳不可用时先使用 `outputLatency`，缺少该值时才使用 `baseLatency`；
- 移除手动/麦克风校准入口、测试音、额外补偿和新增预热/稳定性等待；不请求麦克风，也不保存新的音频设置；
- 页面启动只清理本站点旧 `v1` / `v2` / `v3` 校准键，保留语言偏好和其他数据；删除失败明确提示，旧值仍不会被读取或用于播放；
- 此次恢复仅覆盖播放同步与校准相关代码；现有界面样式、双语、乐谱与指法修正、识谱校对、访问期上传和导出保持现有实现。主机回环采样不等于用户终端的声学到达时间，恢复基线不代表最终音画偏差已经解决；
- 成品谱面点击任意音符会从该事件的规范拍位重新排程，谱面、进度条、键盘动画和音频一起跳转；“从头重新播放”会关闭小节循环并从第 0 拍启动；
- 校对选中态仅显示在校对界面，成品谱面只显示播放时钟驱动的当前音，避免历史选中音被误认为播放进度。
- 自动跟随分别判断横向与纵向可见性；靠近页面左缘的弱起音只会在必要时调整横向位置，不会错误推动整张谱纸向下；
- 连续同音事件按事件标识重新触发琴键反馈，并显示对应歌词提示，两个相同音高的弱起不会再看起来像一个持续音。
- 谱面高亮与琴键激活使用同一次 React 提交；琴键活动色从首帧即完全可见，键盘视口在绘制前完成定位；钢琴音色起音由 12 ms 缩短为 4 ms，减少“谱面先亮、琴键或声音稍后到”的感知差。

### 练习视图与一致性门禁

- 界面采用波普外壳、绘本式圆角引导、贴纸状态反馈和严格信息网格；A4 谱纸保持克制的白底高对比；
- 已确认成品重新进入编辑审核时会退出紧凑练习布局，原图、可点击校对谱和音符校对器恢复完整审核高度；
- 待确认区支持用户显式“一键确认全部音符”，批量确认后仍会执行完整谱面与时间线门禁；
- 竖版 A4 谱面使用独立滚动容器，播放时只滚动谱面，不再带走琴键和控制区；
- 原稿模式严格保留来源谱行分组，只在音符上方增加指法，和弦与左手分析移入练习模式；
- 琴键与演奏控制位于谱面下方，窄屏琴键保持可读尺寸并自动定位左右手活动范围；
- 谱面事件与右手演奏事件逐项核对音高、起点、时值、指法、小节和来源标识；
- 校对后默认只播放右手旋律，用户可按需开启左手伴奏；
- `劳动最光荣` 的谱面、播放、键盘和导出保留原图 `1=♭B`；公开参考页只用于约 ♩=118 的速度参考，不再覆盖源谱调号和音序；
- 相邻同音高延音线在谱面和时间线中保留，Web Audio 与 MIDI 合并为一次连续发声，MusicXML 输出标准 tie 标记；
- 圆滑线与延音线分开建模：圆滑线仅表达乐句/一字多音，不合并音频攻击，MusicXML 输出 slur 标记；
- 乐句末尾的显式休止不再继续生成左手伴奏；
- MIDI 尾标记覆盖完整谱面时长，不再截断末尾休止；
- JSON 保留包含显式休止的规范谱面，MusicXML 使用 480 divisions 精确表达常用细分时值；
- Web Audio 启动加入代次取消，暂停、停止和拖动可撤销尚未完成的启动；
- 用户确认校对时创建并恢复 AudioContext，不安排静默预热音或等待输出时钟稳定；正式播放再次等待 `resume()` 完成后统一排程；
- “确认校对结果”之后保留分阶段生成进度，检查规范谱面、完整演奏时间线、开头四个来源小节的音符起点与时值、谱面/琴键动画激活和实际 Web Audio 排程窗口；音频上下文恢复后直接显示教学谱，不再进入校准步骤；
- 音频排程与生成门禁共用 `buildAudioEventWindows`，避免“校验一套、实际播放另一套”的实现漂移；不使用全局、歌曲或固定拍数补偿；
- 简谱 Reader 必须返回数字、上下八度点、下划线、附点和延长线的结构化几何证据；八度点未与数字中心对齐、时值与线/点证据矛盾或两个 Reader 的点位证据不同，均不得进入 reader-agreed；
- 低于 90% 的结果必须逐音确认，未清空待确认队列时禁止生成成品；
- 识别结果校验音名拼写、原始简谱 token 与 MIDI 是否一致，并拒绝重复标识、重叠、非有限时值和无效锁定和弦。

当前页面使用 React/HTML/CSS 渲染；完整 SVG 排版引擎属于 M2。

当前规范谱面仍是单声部数字简谱模型；已支持相邻同音高的延音线，同一时刻多音和弦、跨声部连线及独立复调声部仍需在后续契约版本中显式建模。

### 产品上传识别

- 同源 Node 服务端代理 OpenAI Responses API 与 Gemini multimodal API，密钥不进入浏览器；
- 支持一次选择 1–4 张乐谱图片，按选择顺序标记页码并合并为连续小节；
- OpenAI 与 Gemini 独立读取全部页面；音乐内容一致时跳过 Judge，存在差异时由 OpenAI Judge 对照原图裁决；
- Judge 必须显式返回无法可靠裁决的事件位置和原因；这些事件会被压到人工校对阈值以下，不会被标记为已确认；
- 识别结果先校验上传页面覆盖和 unresolved 事件定位，再转换为与样例相同的 `SongModel`，随后复用指法、和声、A4 排版、校对、音频、动画和导出流程；
- 服务未配置密钥或任一 Reader 失败时明确返回错误，不使用成功形状的降级结果。

### 双语与访问期乐谱

- 中文和英文界面由同一套类型化词典驱动，语言切换会同步更新页面语言和标题；语言偏好可以保留；
- 标题、导航、说明、音乐术语、状态、错误、加载阶段、控制项和无障碍标签均随语言切换，内置测试曲只改变展示名称，不改变规范谱面标识或来源数据；
- 每次访问可保留并切换多份上传乐谱；每份乐谱可单独删除，删除时立即释放其图片对象 URL；
- 上传图片和识别结果只存在当前页面内存中，不写入 localStorage、IndexedDB、服务端数据库或 URL；刷新、关闭或重新打开页面后自动清空，也不会出现在其他用户的访问中。
